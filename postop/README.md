# 术后跟诊工作台（医生端）

医院端的**分类管理**看板。核心不是「展示所有病例」，是回答一个问题：

> 今天这 24 个术后病人里，哪几个需要我管？

所以默认视图只显示需要处理的，恢复正常的折起来不占注意力。

## 跑起来

纯静态，没有构建步骤。本地看：

```bash
cd jiulingmao.github.io && python3 -m http.server 8899
```

然后开 http://127.0.0.1:8899/postop/

推上去之后是 https://www.jiulingmao.com/postop/

数据全在浏览器里生成（`demo-data.js`），不连后端、不写服务器，可以直接给医生演示。

## 分桶规则

| 桶 | 条件 | 医生要做什么 |
|---|---|---|
| **需处理** | 综合分级 = 红 | 今天联系主人 |
| **观察中** | 综合分级 = 黄 | 盯着趋势，明天再看 |
| **失联** | 连续 ≥2 天没上报 | 打电话提醒 |
| **恢复正常** | 绿 | 不用管 |
| **已结束** | 跟诊周期已满 | 归档 |

**「失联」必须单独成一档**，不能混进绿色里——医生要的是「每天上报」，
没报本身就是信号。混进绿色就等于把失联的病人当成康复的。

排序：`sort_key` 降序，所以「红且在恶化」排最前，医生一打开就看到最该看的那个。

## 分级从哪来

`shared/ai.js` 的 `classify()`：问卷分级和 AI 初筛是两条独立证据，取更保守的一条，
再叠加趋势/可信度/漏报三条升级规则。完整规则见 `postop_front/README.md` 第四节。

> ⚠️ `shared/rules.js` 和 `shared/ai.js` 是从 `postop_front/utils/` **原样复制**的。
> 两边必须同步，否则主人看到的结论和医生看到的会不一样。改动只改 `postop_front/utils/`，
> 然后 `cp postop_front/utils/{rules.js,ai.js} jiulingmao.github.io/postop/shared/`。

## 病例详情里有什么

- **逐日趋势条** — 点任意一天看当天记录，斜纹格 = 那天没上报
- **同角度对比** — 上一次 vs 最新，医生说的「轻微红肿」就靠这个看方向
- **AI 初筛** — 诊断 / 变化趋势 / 逐项观察 / 建议 / 复查时点 / 升级信号 / 可信度
- **问卷逐项** — 异常项着色，正常项也列出来（医生要知道哪些问过了）
- **医生操作** — 回复主人（带快捷话术）/ 通知来院 / 调整分级

**调整分级**是刻意留的：医生说「这个不是问题」时应该能一键压绿，
这个数据反过来还能校准 `rules.js` 的阈值——医生改判得越多，说明规则越该调。

## 和现有 doctor/ 的关系

`jiulingmao.github.io/doctor/` 是九龄猫医生端（问诊 + 客户 + 待办），
那边的 `queueGroups()` 已经是红/黄/绿队列，但数据源是 AI 扫描记录，不是跟诊上报。

这里独立成一个页面，是为了不动那 82KB 的生产代码。
demo 过了、医生认可了，再决定是合并进 `doctor/` 还是独立成医院端产品。
